# Official references for the live-integration work

Research date: **October 9, 2026**. Only official Twilio sources were used. This research verifies documented capabilities and constraints; it does not verify any account, sender registration, legal suitability, recipient permission or real delivery. No credentials, signed-in account, real number or paid resource was used.

## Verified public documentation

| Source | Verified information | Consequence for this project |
|---|---|---|
| [Test credentials](https://www.twilio.com/docs/iam/test-credentials) | New Console users cannot create test credentials; previously created legacy credentials continue to work. They do not connect to real numbers, charge or modify the live account. Test-credential SMS/calls do not generate status callbacks. | A test-credential result is simulated API behavior, not an end-to-end SMS test. Do not promise these credentials are available in a new account. |
| [Trial account overview](https://www.twilio.com/docs/usage/trials) | Current flow is a 30-day trial with product-specific units, including 100 SMS units. Up to five verified recipients, signup-country limits and predefined content apply; custom message bodies are unavailable in trial. Resources can vary by product/recipient. | Do not assume a free trial can run our custom FAQ/request reply texts. This project's account eligibility and entitlements are unknown. |
| [Trial setup details](https://www.twilio.com/docs/usage/tutorials/how-to-use-your-free-trial-account) | Verification and number capabilities must be checked. A2P registration requires a paid account. Toll-free verification and country-specific requirements apply where relevant. Legacy/new Console details differ. | Inspect the actual account/number through an explicitly authorized setup process; do not infer sending eligibility from having an Auth Token. |
| [Try out SMS](https://www.twilio.com/docs/usage/trials/try-out-sms) | The guided flow specifies verified US recipients and predefined outbound examples. It also describes inbound Custom Auto-Reply webhooks and later API use. | A webhook option is not proof that arbitrary custom outbound content is permitted. Resolve flow-specific availability against the actual account/provider support before custom E2E testing. |
| [Advanced Opt-Out](https://www.twilio.com/docs/messaging/tutorials/advanced-opt-out) | Long-code STOP variants are handled by Twilio. Configured START/UNSTOP and HELP behavior differs by sender type; HELP does not alter the block list. `OptOutType` signals the provider already acknowledged the keyword. Toll-free START can produce carrier and custom acknowledgements. | Store provider state without a second application acknowledgement. START must still pass local purpose/permission and other gates. Budget provider-generated messages too. |
| [Error 21610](https://www.twilio.com/docs/api/errors/21610) | The recipient has unsubscribed from the sender/Messaging Service. START or a supported opt-in is required before provider sending can resume; consent remains necessary. | Never call the send API merely to probe an opted-out recipient. Verify suppression locally and model this provider error in a mock. |
| [Standard opt-out help](https://help.twilio.com/articles/223134027-Twilio-support-for-opt-out-keywords-SMS-STOP-filtering-) | Official help page was indexed but its full content could not be retrieved in this session. | Detailed default acknowledgement wording/routing for the chosen sender remains unverified. Advanced Opt-Out and error documentation are the retrieved primary evidence; inspect actual settings before activation. |
| [Outbound status callbacks](https://www.twilio.com/docs/messaging/guides/outbound-message-status-in-status-callbacks) | Initial create status is returned by the API, without an initial callback. Later statuses include sent/failed and delivered/undelivered. Read receipts are for supporting channels such as RCS/WhatsApp. | Treat API acceptance, carrier acceptance, delivery report and participant receipt as separate evidence. Do not label an SMS as read from an SMS delivery callback. |
| [Messages resource](https://www.twilio.com/docs/messaging/api/message-resource) | Stable SID, account/direction/body/address and creation time are available through authenticated retrieval. `numSegments` can initially be zero for Messaging Services. SMS is billed per segment sent/received; encoding and length affect segment count. | Check identity and freshness with trusted data; record final segment/price information. Preview generated text before sending, including Unicode. Message count alone is no spending cap. |
| [Webhook security](https://www.twilio.com/docs/usage/security) | The official SDK validates the signature against the Auth Token, exact public URL and applicable parameters. HTTPS, whitespace handling and token secrecy matter. | Validate signatures before effects, with a configured canonical URL and trusted proxy setup. Signature validity does not itself prove event freshness. |
| [API error 20500](https://www.twilio.com/docs/api/errors/20500) | Sending SMS through POST is explicitly non-idempotent; retrying a 500 can create duplicate messages. | A local unique outbox key cannot guarantee exactly-once carrier delivery. Quarantine ambiguous send outcomes for reconciliation, rather than blindly retrying. |
| [API best practices](https://www.twilio.com/docs/usage/rest-api-best-practices) | API keys support REST authentication; webhook validation needs account Auth Token. Keys can be revoked and rate limits need review. | Separate REST credentials from signature-verification credentials and restrict their use. General retry guidance does not override the non-idempotent SMS-create warning. |
| [A2P 10DLC](https://www.twilio.com/docs/messaging/compliance/a2p-10dlc) | Application messaging to the US through applicable local 10-digit senders requires registration. Other sender types have their own requirements. | Verify actual sender/campaign approval. Readiness code and successful mock tests are not carrier approval. |
| [Messaging Policy](https://www.twilio.com/en-us/legal/messaging-policy) | Consent is purpose-specific. Inbound SMS can authorize that conversation, not unrelated recurring messages. Withdrawal must stop regular messages, with one final confirmation permitted. | Collect actual evidence. Synthetic consent rows do not authorize real messages; manual sending remains subject to suppression. |
| [Dial action](https://www.twilio.com/docs/voice/twiml/dial) | `DialCallStatus` describes the dial outcome; completed is answered/connected. Voicemail can answer an otherwise missed human conversation. | Real voice/missed-call validation is outside the initial SMS E2E plan and needs a separate authorized test. |

## What was not verified

- Any real account, new or legacy Console capability, trial/custom-content entitlement, paid status, phone number, recipient/device ownership or registration approval.
- Real send/API resource resolution, inbound/outbound callback delivery, carrier receipts, participant receipt, STOP/START provider behavior or incurred charges.
- Live model behavior. This project's rule/mock evidence is not evidence of a live model.
- Target country, sender type and account currency; therefore no numeric live-test cost quote is provided. Pricing and any free-unit entitlement need a dated account/route-specific review before approval.

The code/report owner must state which local tests were actually executed. These notes do not convert mocked statuses into real results or authorize any external operation. For a proposed controlled trial, use [REAL_E2E_PLAN.md](REAL_E2E_PLAN.md).
